# Подробное руководство по коду

Проект — браузерный генератор пиксельных фэнтези-карт. Никаких готовых картинок и
библиотек: карта целиком вычисляется в коде и рисуется по пикселям.

Документ описывает архитектуру, модель данных и все типовые функции по секциям.

---

## 1. Общая картина

### 1.1. Слои приложения

Код разделён на независимые уровни, каждый из которых ничего не знает о внутренностях
соседнего:

```
index.html          — разметка и кнопки интерфейса
  main.js           — «клей»: создаёт генератор и рендерер, вешает обработчики кнопок
    map-generator.js  — ЛОГИКА МИРА: рельеф, климат, ресурсы, реки, регионы, поселения, дороги
    seasons.js        — палитры сезонов (весна/лето/осень/зима) и тёмного стиля
    map-painter.js    — РЕНДЕР: превращает логическую карту в холст с пикселями
    map-renderer.js   — КАМЕРА: показывает нужный кусок холста, зум, выделение клетки
    sprite-renderer.js — объекты поверх карты (города, армии), рисуются по конфигу
```

Ключевая идея производительности: **карта рисуется один раз** в большой скрытый холст
в масштабе 1:1 (`MapPainter`), а `MapRenderer` только показывает из него нужный
прямоугольник с зумом. Поэтому панорамирование и зум дешёвые, а перерисовка карты
происходит только при смене вида, сезона или стиля.

### 1.2. Поток данных

```
MapGenerator.generate(seed)
   → заполняет плоские массивы (terrain, biome, river, regionId, ...)
MapPainter.paint({ view, seasonName, showBorders, mood })
   → читает массивы и палитру сезона, пишет пиксели в ImageData, возвращает холст
MapRenderer
   → drawImage(холст) с учётом камеры, рисует сетку/границы/выделение/объекты поверх
```

Генератор и painter не вызывают друг друга напрямую: painter читает **только** поля
объекта карты. Это позволяет тестировать генерацию без DOM (как в проверках ниже).

## 2. Модель данных `MapGenerator`

Вся карта — это плоские массивы длиной `size * size`. Клетка `(x, y)` имеет индекс
`i = y * size + x`. Обратное преобразование: `x = i % size`, `y = Math.floor(i / size)`.

Почему плоские типизированные массивы (`Float32Array`, `Uint8Array`): они компактны,
не создают мусор для сборщика и быстро читаются в горячих циклах.

### 2.1. Справочники (перечисления)

| Константа   | Значения                                                                 |
|-------------|--------------------------------------------------------------------------|
| `Terrain`   | `DEEP_WATER=0`, `SHALLOW_WATER=1`, `PLAIN=2`, `MOUNTAIN=3`                |
| `Biome`     | `TUNDRA=0`, `TAIGA=1`, `GRASSLAND=2`, `STEPPE=3`, `DESERT=4`, `SAVANNA=5` |
| `Shore`     | `NONE=0`, `BEACH=1`, `ROCKY=2`, `CLIFF=3`                                 |
| `Resource`  | `NONE=0`, `WOOD=1`, `WHEAT=2`, `GOLD=3`, `ETHER=4`, `IRON=5`, `SETTLEMENT=6` |

`isLand(i)` — «суша ли это» — определяется как `terrain[i] >= Terrain.PLAIN`.

`ResourceInfo` — таблица «что даёт ресурс» (`name`, `produces`), её использует интерфейс.

`ROAD_DIRECTIONS` — 8 направлений дороги. Направление `d` и `7 - d` — противоположные
(это используется, чтобы восстановить связь между клетками по битовой маске).

### 2.2. Основные поля после `generate()`

| Поле                | Тип            | Смысл                                                    |
|---------------------|----------------|----------------------------------------------------------|
| `elevation`         | `Float32Array` | высота (сырой шум + хребты)                              |
| `moisture`          | `Float32Array` | влажность 0..1 (выровнена по рангу)                      |
| `ridge`, `massif`   | `Float32Array` | «хребтовость» и «массивность» для гор                    |
| `temperature`       | `Float32Array` | температура 0..1 (север холодный)                        |
| `terrain`           | `Uint8Array`   | рельеф (`Terrain`)                                       |
| `biome`             | `Uint8Array`   | биом (`Biome`)                                           |
| `waterDepth`        | `Uint8Array`   | глубина воды = расстояние до суши                        |
| `river`             | `Uint8Array`   | 0 — нет реки, 1..3 — глубина                             |
| `riverTo`, `riverFlow` | `Int32Array` / `Uint16Array` | куда течёт река и сколько воды через клетку |
| `shore`             | `Uint8Array`   | тип берега (`Shore`)                                     |
| `crossing`          | `Uint8Array`   | 0/1 брод/2 мост                                          |
| `resource`          | `Uint8Array`   | ресурс (`Resource`)                                      |
| `mountainHeight`    | `Float32Array` | высота гор 0.3..1 (для рельефа painter'а)                |
| `regionId`          | `Int16Array`   | номер региона, -1 — вода/река/вне региона                |
| `regionSizes`       | `Object`       | id региона → число клеток                                |
| `landTiles`         | `Array`        | индексы всех клеток суши                                 |
| `population`, `settlementLevel`, `settlementGroup` | массивы | данные поселений |
| `roadLevel`, `roadLinks` | `Uint8Array` | наезженность дороги и биты направлений             |

## 3. `map-generator.js`

### 3.1. `SECTION: MAP_UTILS` — вспомогательные функции

Типовые утилиты, которые переиспользуются во всей генерации.

**`clamp(value, min=0, max=1)`** — ограничивает число диапазоном. Значения по умолчанию
(`0..1`) выбраны так, чтобы в большинстве мест вызывать просто `clamp(v)`.

**`hash32(n)`** — быстрый хеш числа в диапазон `0..2^32`. Даёт «несвязанные» значения для
соседних номеров клеток. В комментарии отмечено, почему нельзя обойтись простым умножением:
оно давало «решётчатые» узоры (реки бежали параллельными полосами).

**`lerp(a, b, t)`** — линейная интерполяция `a + (b - a) * t`.

**`createRandom(seed)`** — генератор псевдослучайных чисел (mulberry32). Возвращает функцию
`random()`. Ключевое свойство: **один seed даёт одну и ту же последовательность** — карта
воспроизводима.

**`rankNormalize(values)`** — выравнивает значения до равномерных `0..1` **по рангу**:
самое малое станет 0, самое большое — 1. Это позволяет порогам вида «нижние 40%» работать
честно, независимо от того, как шум «слипается» вокруг 0.5.

**`percentile(values, share)`** — значение на заданной доле отсортированного списка
(`0.5` — медиана). Используется, чтобы задавать уровень моря и порог гор долями, а не
абсолютными числами.

### 3.2. `SECTION: MAP_NOISE` — класс `ValueNoise`

Плавный шум: значения `0..1`, соседние точки похожи.

- **`constructor(seed)`** — строит решётку `65×65` случайных чисел (запас `+1` для
  интерполяции, размер 65 — степень двойки + 1, чтобы работала маска `& 63`).
- **`latticeValue(ix, iy)`** — значение узла решётки с заворотом по маске `& 63`.
- **`sample(x, y)`** — одна «октава»: билинейная интерполяция между четырьмя ближайшими
  узлами со сглаживанием `t*t*(3-2t)`.
- **`fractal(x, y, octaves)`** — несколько октав: крупные формы плюс всё более мелкие
  детали; амплитуда делится на 2, частота умножается на 2, результат нормируется.

### 3.3. `SECTION: CONSTRUCTOR` / `DEFAULTS`

- **`constructor(options)`** — сливает переданные опции с `MapGenerator.DEFAULTS`.
- **`static get DEFAULTS()`** — полный список параметров генерации с комментариями
  (доли воды и гор, масштабы шума, климат, ресурсы, поселения, дороги). Это
  **единственное место**, где нужно менять настройки по умолчанию; `main.js` может
  переопределить любое поле.

### 3.4. `SECTION: GENERATE` — главный конвейер

**`generate(seed)`** — точка входа. Порядок вызовов — это и есть зависимость шагов:

```
seed → random → createNoiseLayers → allocateLayers
generateElevation → scatterIslands → generateMoisture → classifyTerrain
removeSmallMountains → removeSmallIslands → collectLandTiles
fillDepressions → computeWaterDepth → generateTemperature → assignBiomes
placeResources → generateRivers → classifyShores → placeRareResources
placeRiverCrossings → buildRegions → placeSettlements → buildRoads
```

Возвращает `this` (цепочка вызовов). Важен порядок: реки текут по уже готовым высотам,
регионы строятся после рек (реки — границы регионов), поселения — после регионов, дороги —
после поселений.

### 3.5. `SECTION: STATS`, `GRID`

- **`get landShare()`** — доля суши: `landTiles.length / size²`.
- **`get regionCount()`** — число регионов: число ключей в `regionSizes`.
- **`index(x, y)`** — `y * size + x`.
- **`neighbors(i)`** — до 4 соседей по сторонам (внутри карты).
- **`neighbors8(i)`** — до 8 соседей с диагоналями.
- **`isLand(i)`** — `terrain[i] >= Terrain.PLAIN`.

### 3.6. `SECTION: NOISE & LAYERS`

- **`createNoiseLayers()`** — создаёт 17+ генераторов `ValueNoise` с разными seed-солями
  (`elevation`, `ridge`, `temperature`, `moisture`, `warpX/Y`, `forest`, ...). Разные
  соли — чтобы слои были независимы друг от друга.
- **`allocateLayers()`** — выделяет все плоские массивы (см. таблицу 2.2) и начальные
  значения (`regionId` и `riverTo` заполняются `-1`).

### 3.7. `SECTION: ELEVATION`

- **`generateElevation()`** — базовый рельеф. На клетку складываются:
  1. фрактальный шум высоты;
  2. спад к краям (`falloff`) — мир окружён водой;
  3. «регулятор формы» — среднемасштабный шум ломает береговую линию (заливы, острова);
  4. внутренние моря — крупные впадины;
  5. хребты — линии, где шум близок к 0.5, поднятые вверх;
  а координаты предварительно «скручиваются» (warp), чтобы берега были извилистыми.
- **`scatterIslands()`** — в полосе мелководья поднимает отдельные «горбы» шума над
  уровнем моря. Порог зависит от `islandDensity`.

### 3.8. `SECTION: MOISTURE`

- **`generateMoisture()`** — фрактальный шум влажности, затем `rankNormalize` — чтобы
  порог «сухие 40%» работал предсказуемо.

### 3.9. `SECTION: TERRAIN` — вода / равнина / гора

- **`classifyTerrain()`** — задаёт уровень моря как `percentile(elevation, waterShare)`,
  затем горы = ранг «хребтовости» + «массивности» + немного высоты. Горы задаются долей
  суши (`mountainShare`), а не абсолютной высотой.
- **`removeSmallMountains()`** — убирает горные кляксы меньше `minMountainSize` клеток
  (заливкой `flood fill` по 4 соседям).
- **`removeSmallIslands()`** — убирает клочки суши меньше `minIslandSize`.
- **`collectLandComponent(start, visited)`** — BFS-обход связного куска суши от `start`.
- **`collectLandTiles()`** — собирает все клетки суши в `landTiles`.
- **`computeWaterDepth()`** — глубина воды = расстояние до ближайшей суши (BFS от суши).

### 3.10. `SECTION: CLIMATE & BIOMES`

- **`generateTemperature()`** — «север холодный, юг жаркий» + шум, высота охлаждает.
- **`assignBiomes()`** — каждой клетке суши присваивает биом по температуре и влажности.
- **`pickBiome(temperature, moisture)`** — таблица «температура × влажность → биом».

### 3.11. `SECTION: RESOURCES`

- **`placeResources()`** — ставит дерево и пшеницу по слоям «пятен».
- **`createPatchLayer(...)`** — «пятна» ресурса: крупные скопления + мелкие разрозненные
  кучки (хаотичное, но не пустое распределение).
- **`createDensityLayer(noise, scale)`** — слой плотности: шум, выровненный по рангу.
- **`placeRareResources()`** — вызывает `placeGold()`, `placeIron()`, `placeEther()`.
- **`placeGold()` / `placeIron()`** — руда в горах и предгорьях скоплениями (железо чаще).
- **`tilesNearMountains(distance)`** — маска «гора или суша не дальше N клеток от гор».
- **`placeEther()` / `createFaultLayer()`** — эфир вдоль «линий разлома».
- **`classifyShores()`** — тип берега: горы у воды — всегда утёсы; низкие тёплые берега —
  пляжи (пятнами); остальное — камни.

### 3.12. `SECTION: RIVERS`

- **`fillDepressions()`** — «заливает» впадины, чтобы вода всегда находила сток.
- **`isDiagonal(a, b)`** — диагональные ли клетки (для проверки разрывов русла).
- **`generateRivers()`** — вода стекает по высотам (рёбра — `MinHeap` по перепаду высот).
- **`placeRiverCrossings()`** — на прямых участках рек изредка ставит мост или брод.

### 3.13. `SECTION: REGIONS` — самый большой раздел

Регион — связный кусок суши **без рек** (реки остаются границами). Алгоритм:

1. **`buildRegions()`** — конвейер: семена → деление → релаксация → починка → слияние →
   выравнивание → сглаживание → перенумерация.
2. **`shuffled(list)`** — копия массива в случайном порядке (Фишер—Йетс).
3. **`buildRegionCosts()`** — цена «зайти» в клетку: единица + шум + горы (преграда).
4. **`regionNeighbors(i)`** — соседи для роста региона: 4 стороны + диагонали; диагональ
   разрешена, только если обе клетки «за углом» тоже годятся (регион не просачивается
   сквозь диагональный изгиб реки).
5. **`regionAreas()`** — отдельные массивы региональной суши.
6. **`pickRegionSeeds(area, count)`** — семена случайно, но не вплотную (сначала с большим
   зазором), равнинам предпочтение.
7. **`markBlocked(blocked, i, radius)`** — помечает занятые клетки вокруг семени.
8. **`assignRegions(seeds)`** — **Дейкстра от всех семян сразу**: каждая клетка достаётся
   тому, до кого «дешевле» дойти.
9. **`relaxRegionSeeds(seeds)`** — релаксация Ллойда: новое семя — клетка, ближайшая к
   центру тяжести региона (со штрафом за горы). Именно она превращает клочки в ровные
   почти шестиугольные области.
10. **`repairRegionConnectivity()`** — обрывки, отрезанные от основной части, отдаёт соседу
    с самой длинной общей границей.
11. **`bestNeighborRegion(tiles, ownId)`** — сосед с самой длинной общей границей.
12. **`countRegionSizes()`** — пересчитывает `regionSizes`.
13. **`mergeSmallRegions()`** — вливает слишком мелкие регионы в соседей.
14. **`regionAcrossRiver(tiles, ownId)`** — клочок за рекой присоединяет к региону на другом
    берегу.
15. **`regionContacts(tile, id)`** — сколько из 8 соседей принадлежит региону.
16. **`balanceRegionSizes()`** — выравнивает размеры: граничные клетки переходят от больших
    регионов к маленьким (клетку не отдают, если донор развалится).
17. **`smoothRegionBorders(minFactor, maxFactor)`** — сглаживание границ: клетка с
    большинством «чужих» соседей одного региона переходит к нему.
18. **`staysConnectedWithout(removed, id)`** — проверка, не расколется ли регион, если
    убрать клетку.
19. **`renumberRegions()`** — номера подряд `0, 1, 2, ...` (после слияний были дыры).

### 3.14. `SECTION: SETTLEMENTS`

- **`placeSettlements()`** — поселение — это ресурс клетки. Для каждого региона считает
  население и ставит одну (или при большом населении — вторую) группу.
- **`settlementLevelFor(population)`** — уровень клетки 1..`settlementMaxLevel`.
- **`isSettlementSite(i, ...)`** — подходит ли клетка под поселение.
- **`growSettlementGroup(...)`** — выбирает лучшую клетку региона и наращивает вокруг неё
  группу из соседних клеток.
- **`commitSettlementGroup(...)`** — записывает группу: делит население между клетками
  (центр — больше всех), задаёт уровни и дорожки.
- **`computeHabitability()`** — «обитаемость» клетки 0..~1.6 (плодородный луг у реки —
  максимум).

### 3.15. `SECTION: ROADS`

- **`buildRoads()`** — каждое поселение соединяется с ближайшими соседями; рёбра берутся по
  «выгодности».
- **`findRoadPath(start, goal)`** — поиск пути A*.
- **`roadStepCost(...)`** — цена шага по дороге (`Infinity` — нельзя).
- **`carveRoad(path)`** — сохраняет путь: уровень дороги в клетках, связи с соседями и мосты
  через реки.

### 3.16. `SECTION: INFO`

- **`getRegionInfo(regionId)`** — сводка по региону: клетки, размер, горы, реки, население,
  поселения, выход к воде, гистограммы ресурсов и биомов.
- **`getTileInfo(x, y)`** — сводка по клетке (используется интерфейсом при наведении/клике).

### 3.17. `SECTION: MIN_HEAP` — класс `MinHeap`

Двоичная куча для «достать самый дешёвый элемент». Используется трижды: сток воды, рост
регионов, поиск дорог.

- **`get size()`**, **`push(cost, tile, region)`**, **`pop()`** — стандартные операции кучи
  с просеиванием вверх/вниз.

## 4. `seasons.js`

Палитры для четырёх сезонов. У каждого сезона — `name`, `tempShift` (сдвиг температуры) и
`palette` с полями `biome`, `rock`, `water`, `river`, `ice`, `snow`, `snowShade`, `broadleaf`,
`conifer`, `trunk`, `blossom`, `wheatStage`, `groundDetail` и флагами `bareTrees`,
`snowOnConifers`.

Сезоны различаются не только цветом, но и тем, **как** рисуется флора (весной — цветущие
деревья, осенью — рыже-золотая листва, зимой — голые лиственные и ели со снегом).

- **`toneHex(hex, {saturation, light, tint})`** — приглушает/затемняет цвет (для тёмного
  стиля).
- **`DARK_TONES`**, **`DARK_EXTRA`** — параметры приглушения по типам поверхностей и
  доп. настройки сезона (`deadTreeChance`, `fogStrength`).
- **`DARK_SEASONS`** — собирается циклом: копия каждого сезона с приглушённой палитрой и
  пониженной температурой (мир холоднее — снег ложится раньше).

## 5. `map-painter.js`

### 5.1. Файловые секции (константы и утилиты)

**`SECTION: MAP_COLORS`**
- `COLORS` — палитра, не зависящая от сезона, в виде hex.
- `packRgb(r, g, b)` — упаковывает цвет в одно 32-битное число (порядок `0xFFBBGGRR` —
  как в `Int32Array` для `ImageData`).
- `hexToPacked(hex)`, `WHITE`, `BLACK`.
- `hslToPacked`, `mixPacked(a, b, t)`, `speckColor`, `shadeFast`, `shadePacked` — работа с
  упакованными цветами: смешивание, осветление/затемнение.
- `MOUNTAIN_RAMP` — рамп скалы гор.
- `packPalette(palette)` — превращает hex-палитру сезона в упакованные числа.

**`SECTION: MAP_CONSTANTS`** — пороги снега/льда/замерзания рек, `WATER_DEPTH_STEPS` и
`waterShadeIndex(depth)`, матрица дизеринга `BAYER` и `STEP_AMOUNTS`.

**`SECTION: MAP_HASH & NOISE`**
- `tileHash(x, y, k)` — хеш с хорошим перемешиванием битов (те же причины, что и в
  генераторе).
- `hashUnit(x, y, k)` — тот же хеш, нормированный в `0..1`.
- `smoothstep(t)`.
- **`class LatticeNoise`** — плавный шум с ячейкой `cell` пикселей; решётка и сглаженные
  позиции считаются один раз, потом шум берётся быстро (`at(gx, gy)`).

**`SECTION: MAP_SHADING`** — `computeHillShading({...})` и `applyHillShading(pixels, {...})`.
Светотень холмов не зависит от сезона, поэтому считается один раз: для каждого пикселя
запоминается индекс и «код» (ступень светотени + признак оврага). При перерисовке остаётся
только применить список. Горячий цикл вынесен в отдельную функцию с простыми аргументами —
так движок оптимизирует его лучше, чем кусок большого метода.

**`SECTION: PIXEL_BUFFER`** — **`class PixelBuffer`**: маленький буфер для спрайтов (дома,
руды, эфир). Прозрачный фон (`0`), рисование фигур, контур. Рисунок готовится один раз, потом
копируется на карту.
- `put(x, y, color)`, `rect(...)`, `ellipse(cx, cy, rx, ry, base, light, dark)` (эллипс с
  объёмом), `outline(color)` (контур вокруг силуэта).

### 5.2. `SECTION: CONSTRUCTOR & MAIN` — класс `MapPainter`

- **`constructor(map, options)`** — сохраняет карту и опции (размер клетки, резкость
  смешивания, острота гор, плотность оврагов, сглаживание берега, прозрачность сетки, флаги
  слоёв и т.д.). `undefined` не затирает значения по умолчанию. Создаёт холст и кэш
  упакованных цветов.
- **`paint({ view, seasonName, showBorders, mood })`** — главный метод. Порядок:
  1. выбирает сезон (обычный или тёмный) и упаковывает палитру;
  2. создаёт `ImageData` и `Int32Array` поверх его буфера;
  3. `paintBase()` (фон с дизерингом) → `smoothCoast()` (сглаживание берега);
  4. если вид `terrain` — рельеф, холмы, берега, реки, дороги, земля поселений;
  5. текстура; границы регионов; сцена (горы + декорации);
  6. в тёмном стиле — цветокоррекция и туман; затем источники света;
  7. `putImageData` и возврат холста.
  Слои можно отключать опцией `layers` (для быстрой разработки).

- **`px(n)`** — «пиксели для клетки 12×12» → пиксели текущей клетки.
- **`pxMin(n)`** — то же, но не меньше 1 пикселя (тонкие детали спрайтов не исчезают при
  мелкой клетке).
- **`tileOf(k)`** — клетка, которой принадлежит пиксель `k`.
- **`forEachTile(callback)`** — обход всех клеток `(x, y)`.
- **`seasonalTemperature(i)`** — температура клетки с учётом сезона.

### 5.3. `SECTION: PIXEL PRIMITIVES`

Базовые операции с буфером карты (`this.pixels` — `Int32Array` ширины `this.width`):
- **`put(x, y, color)`** — пиксель с проверкой границ;
- **`blend(x, y, color, alpha)`** — смешать с фоном;
- **`rect(x, y, w, h, color)`** — прямоугольник;
- **`linePoints(x0, y0, x1, y1)`** — точки отрезка (Брезенхэм).

### 5.4. `SECTION: BACKGROUND` — фон и дизеринг

- **`paintBase()`** — цвет каждой клетки «живёт» в её центре; пиксель лежит внутри квадрата
  из центров четырёх ближайших клеток; вес — как при билинейной интерполяции, но вместо
  смешивания цветов выбирается один из четырёх **через дизеринг**. Получается пиксельный
  градиент: у «ступенек» пиксели плавно уходят в цвет соседей, внутри однотонных областей
  ничего не меняется.
- **`blendGrid()`**, **`blendChoices(tx, ty)`** — три таблицы выбора (мягкая, береговая,
  «ближайший сосед») для клетки с данным сдвигом узора дизеринга.
- **`buildAxisTables()`** — для каждого пикселя по одной оси: между центрами каких клеток он
  лежит и на каком расстоянии.
- **`isUniform(colors, tx, ty, color)`** — все 8 соседей одного цвета?
- **`smoothCoast()`** — сглаживает береговую линию (см. одноимённую секцию).

### 5.5. `SECTION: TILE COLOR`

- **`buildTileColors()`** — цвет каждой клетки + признак «вода».
- **`isRiverTileInRegionsView(i)`** — в режиме регионов реки показываются как вода.
- **`tileColor(i)`** — цвет клетки по виду (рельеф/температура/регионы).
- **`waterColor(i)`** — вода темнее к глубине; в холод у берега лёд.
- **`groundColor(i)`** — цвет биома с поправкой на плодородие и снег.
- **`snowCoverage(i)`** — доля снега: 0, 1/3, 2/3 или 1 («пиксельные» ступени).
- **`nearRiver(i)`** — клетка рядом с рекой (считается один раз на карту).
- **`fertilityTint(i, color)`** — внутри биома цвет зависит от плодородия.
- **`shadeStep(color, step)`** — цвет, осветлённый/затемнённый на `step` ступеней (−2..2).

### 5.6. `SECTION: HILLS`

- **`paintHills()`** — применяет предрасчитанную светотень холмов.
- **`buildHillHeights()`** — карта холмов по пикселям (`0..255`); от сезона не зависит,
  поэтому кэшируется.

### 5.7. `SECTION: SHORES`

- **`paintShores()`** — пляжи, каменистые берега, утёсы (по сглаженной береговой линии).
- **`paintCliffs(queue, distance, kind)`** — утёсы: суша «приподнята», под южным краем
  стенка из камня и тень на воде. Идёт по тем же пикселям берега, поэтому сглаженная линия
  не рвёт обрыв.

### 5.8. `SECTION: MOUNTAIN RELIEF`

- **`buildReliefHeights()`** — карта высот гор: огибающая (высоты клеток из генератора)
  умножается на «складчатый» рельеф — мультифрактал из нескольких масштабов гребней.
  Кэшируется (не зависит от сезона).
- **`blurHeights(height, zone, radius)`** — размытие по строкам, потом по столбцам, только
  в клетках с горами.
- **`prepareReliefRows()`** — готовит строки карты высот к отрисовке.
- **`paintReliefRow(relief, gy)`** — одна строка → экран; горы поднимаются вверх, пустоты
  между строками закрашиваются цветом склона.
- **`fillColumn(gx, fromY, toY, color)`** — заливка вертикального отрезка.
- **`blurMountainHeights()`** — высоты клеток, дважды размытые по соседям (горы «набухают»
  за пределы клеток, пропадает сетка).
- **`mountainFootprint()`**, **`tilesNearRelief(blurred)`** — где может быть рельеф.
- **`snowLevel(tile)`** — с какой высоты лежит снег (зависит от сезона).

### 5.9. `SECTION: RIVERS`

- **`riverWidthAt(i)`**, **`riverWidth(level)`** — ширина реки по количеству воды.
- **`band(thickness)`** — смещение полосы, чтобы лежала по центру клетки.
- **`paintRivers()`** — рисование рек с мягкой кромкой.
- **`buildRiverGeometry()`** — геометрия рек (маска, расстояния, «солидные» пиксели);
  кэшируется.
- **`paintBankPixel(xx, yy, k, outside, bankColors)`** — берег реки: первый пиксель суши —
  сплошная линия мокрой земли, второй — галька/песок.

### 5.10. `SECTION: TEXTURE`

- **`paintTexture()`** — крапинки, волны, цветы и листва.
- **`speckLayout(speckCount)`** — расположение крапинок (одинаково при любом сезоне, поэтому
  считается один раз).
- **`paintGroundDetail(x, y, i)`** — сезонные мелочи на лугах (весной цветы, осенью листва).
- **`paintTufts(x, y, i)`** — пучки травы (чем плодороднее место, тем гуще).
- **`putGround(x, y, color)`** — пиксель земли (не поверх воды и реки).

### 5.11. `SECTION: GRADE & FOG` (тёмный стиль)

- **`moodize(color)`** — приглушает цвет построек.
- **`applyGrading()`** — цветокоррекция (в тёмном стиле).
- **`buildFog()`** — густота тумана по пикселям; над водой плотнее; считается один раз.
- **`drawLight(x, y, color, glowColor, glowRadius)`** — источник света (окна, костры, эфир);
  рисуется после цветокоррекции, чтобы оставаться ярким.

### 5.12. `SECTION: PROPS`

- **`collectProps(items)`** — кости, вороны, развалины, виселицы (редко, поодиночке).
- **`drawBones`**, **`drawCrow`**, **`drawRuin`**, **`drawGibbet`** — отрисовка каждой детали.

### 5.13. `SECTION: ROADS`

- **`roadWidth(level)`** — ширина дороги по наезженности.
- **`paintRoads()`** — рисует дороги из готовой геометрии.
- **`buildRoadGeometry()`** — пиксели дорог (мягкая полоса утоптанной земли + сама дорога с
  тремя оттенками); кэшируется.

### 5.14. `SECTION: SETTLEMENTS`

- **`settlementLayout(x, y, i)`** — кэширующая обёртка вокруг `layoutSettlement` (раскладка
  не зависит от сезона, считается один раз).
- **`layoutSettlement(x, y, i)`** — раскладка домов в клетке: сколько домиков, их размеры,
  места (случайные точки с проверкой, что дом помещается и не пересекается), улица.
- **`paintSettlementGround()`** / **`settlementGround(layout)`** — утоптанная земля и улица
  (до деревьев и границ).
- **`collectSettlement(items, x, y, i)`** — собирает дома в список отрисовки.
- **`houseColor(color)`**, **`houseSprite(part, roll, snow)`** (кэшируется), **`drawHouse`**,
  **`drawBuildingShadow`**, **`blitSprite(buffer, left, top)`** — отрисовка зданий.

### 5.15. `SECTION: ORE & ETHER`

- **`oreSprite(kind, variant)`** — каменный выступ с рудой (золото яркое с блёстками, железо
  тёмное); кэшируется.
- **`drawOreTile(x, y, kind)`** — кладёт спрайт руды на карту.
- **`etherSprite(variant)`** — кристаллы или гигантские грибы; кэшируется.
- **`drawEther(x, y)`** — кладёт спрайт эфира на карту.

### 5.16. `SECTION: REGION PIXELS`

- **`buildPixelRegions()`** — какой регион у каждого пикселя (или -1). Пиксель наследует
  регион клетки, но берег скруглён, а русла рек уже клеток, поэтому пиксели воды/реки не
  принадлежат никому, а клочки суши без региона достаются ближайшему.
- **`computePixelRegions()`**, **`smoothPixelRegions(owner)`** — расчёт и сглаживание.
- **`paintRegionBorders()`** — тонкая линия на границе регионов; в горах бледнее.

### 5.17. `SECTION: OUTLINES & GRID`

- **`traceOutline(inside, x0, y0, x1, y1, smoothing, keepCorners)`** — обводка по маске с
  опциональным сглаживанием и сохранением прямых углов.
- **`regionOutline(regionId, smoothing)`** — контур региона.
- **`buildCellMap()`** — карта принадлежности пикселей клеткам (один раз на карту).
- **`cellAt(worldX, worldY)`** — индекс клетки в точке мира (или -1).
- **`cellOutline(tile, smoothing, keepCorners)`** — контур выделенной ячейки.
- **`paintGrid()`** — холст с линиями сетки клеток (отдельным слоем, поэтому включение
  сетки не перерисовывает карту).

### 5.18. `SECTION: DECORATIONS`

- **`paintScene()`** — рисует горы и декорации вместе, строка за строкой сверху вниз: то,
  что южнее (ближе к зрителю), перекрывает северное.
- **`collectDecorations()`** — список декораций, отсортированный по «основанию».
- **`collectTrees(items, x, y, i)`** — 2–3 дерева на клетку; вид зависит от климата.
- **`drawShadow`**, **`drawBroadleaf`**, **`drawBareTree`**, **`drawConifer`**,
  **`drawWheat`** — отрисовка растительности.
- **`liftAtTile(x, y)`** — на сколько пикселей поднята поверхность гор в центре клетки.
- **`paintCrossing(x, y, i)`** — переправа (мост/брод).
- **`crossingDirections(x, y, i)`** — в какие стороны идёт переправа.

## 6. `map-renderer.js` — класс `MapRenderer`

Камера и взаимодействие. Показывает кусок холста-буфера с нужным зумом.

- **`constructor(canvas, map, options)`** — создаёт `MapPainter`, буферный холст, камеру,
  `SpriteRenderer`, вешает события и `ResizeObserver`.
- **`refresh()`** — после новой генерации: перестроить буфер и вписать в экран.
- **`setView` / `setSeason` / `setMood` / `setShowSettlements` / `setShowBorders`** —
  меняют параметр и перестраивают буфер.
- **`setShowGrid(show)`** — сетка рисуется отдельным слоем (не перерисовывает карту).
- **`setObjects` / `addObject` / `removeObject`** — объекты поверх карты (города, армии).
- **`objectBox(object)`** — где на экране объект; **`drawObjects()`** — рисует южные поверх
  северных; **`objectAt(point)`** — объект под точкой.
- **`rebuildBuffer()`** — перерисовка карты painter'ом + пересчёт форм выделения.
- **`get worldSize()`**, **`fitToView()`**, **`centerOn`**, **`clampCamera`**, **`panBy`**,
  **`zoomAt`**, **`screenToWorld`**, **`screenToTile`** — камера.
- **`pickTile`**, **`selectAt`**, **`clearSelection`** — выделение клетки и региона.
- **`regionOutline`**, **`regionShape`**, **`cellShape`**, **`draw`**, **`bindEvents`**,
  **`resize`** — геометрия выделения, отрисовка и события.

## 8. `sprite-renderer.js` — класс `SpriteRenderer`

Рисует объекты (города, деревни, армии) по описанию-конфигу, пиксель за пикселем. Формат
конфига подробно описан в шапке файла: `palette` (именованные цвета и их производные),
`layers` (фигуры `rect`/`ellipse`/`polygon`/`line`/`pixels`/`scatter`/`gradient`), `variants`
(отличия по сезону), `when`/`repeat` (условия и повторы).

- **`render(config, options)`** — рисует спрайт и кэширует результат; возвращает
  `{ canvas, width, height, anchorX, anchorY, scale }`.

## 9. Типовые приёмы (паттерны), которые встречаются по всему коду

1. **Детерминированная случайность.** `createRandom(seed)` + `hash32`/`tileHash`/`hashUnit`.
   Никакого `Math.random()` в генерации и отрисовке: карта воспроизводима по seed.
2. **Нормализация по рангу.** `rankNormalize` + `percentile`: все пороги («доля воды»,
   «доля гор», «сухие 40%») задаются долями, а не абсолютными числами, поэтому не зависят от
   настроек шума.
3. **Плоские типизированные массивы** и индекс `i = y*size + x` — компактно и быстро.
4. **Обходы по графу.** BFS (заливка `flood fill`, связность регионов, глубина воды) и
   Дейкстра/`MinHeap` (сток воды, рост регионов, дороги). Куча вынесена в класс `MinHeap`.
5. **Кэширование дорогих расчётов.** `reliefCache`, `riverCache`, `roadCache`,
   `settlementLayoutCache`, `spriteCache`, `shadeCache`, `tuftCache`. Кэш проверяет
   «источник» (`source`) и ключ (размер клетки, соли) и пересчитывается при смене входных
   данных.
6. **Координаты в долях клетки.** Спрайты заданы в «пикселях для клетки 12×12», а `px`/`pxMin`
   переводят их в текущий размер. Поэтому `tileSize` можно менять.
7. **Упакованные цвета.** Цвет — одно `Int32`-число; смешивание и осветление — арифметика
   (`mixPacked`, `shadePacked`). Быстро пишется в `ImageData`.
8. **Предрасчёт и применение.** Тяжёлые слои (светотень холмов, геометрия рек/дорог)
   считаются один раз, затем применяются списком.
9. **Порядок отрисовки = перспектива.** Сцена рисуется строка за строкой сверху вниз, поэтому
   южные объекты перекрывают северные.

## 10. Как запустить и проверить

Открыть `index.html` в браузере. Проверить генерацию без DOM можно так:

```js
// В Node: загрузить map-generator.js и seasons.js, затем
const map = new MapGenerator({ size: 120 }).generate(42);
console.log(map.landShare, map.regionCount);
```

Для painter'а нужен минимальный заглушечный canvas с `createImageData`/`putImageData`
(используется в проверках). Результат генерации и отрисовки при одном seed детерминирован —
это удобно для регрессионных проверок: сравнить карту или холст до и после правки.
